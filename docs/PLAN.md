# Podcast編集ツール 計画メモ


## 要件
- 32bit float対応。編集前にサンプリングレート等を変更可能
- 複数話者ファイルの編集点合わせ（冒頭の拍手。雑談が混じっても正しく判断）
- フェード・BGMカットのタイミングを過去データから学習しつつ、UIで手動編集・移動
- ノイズ除去・EQ・コンプ・ボリューム・レベルメーター。Claudeが自動設定し、後から手動調整
- ラウドネス調整・ノーマライズ
- 文字起こし2表示：①話者と発言を分けた台本（フィラーなし）②波形上のルビ（フィラーあり）。文章でカット・並べ替え
- 保存：音声ファイル＋編集ファイル。出力はmp3
- 取り込み時に自動処理：編集点合わせ／BGM配置（過去データ参照）／ノイズ除去・EQ・コンプ・ノーマライズ・ラウドネス／文字起こし

## 方針
- 非破壊編集。元音声は変えず、編集内容と設定値をプロジェクトファイル（.podproj, JSON）に保持
- Claudeは音声を直接扱わず、解析結果と文字起こしを読んで編集指示をJSONで出す
- 手動修正は正解例として保存し、次回以降の判断に使う（few-shot／スタイルプロファイル）

## 構成
- UI：React + TypeScript + Web Audio API（AudioWorklet）。ブラウザ or Tauri
- 処理エンジン：Python（FastAPI）
  - 入出力 soundfile、リサンプル soxr、エフェクト pedalboard、ノイズ除去 DeepFilterNet（聴き比べで決定、下記）
  - ラウドネス：BS.1770-4 を自前実装（`loudness.py`、長尺でもメモリを抑えるため。pyloudnorm と 0.05 LU 以内で一致することをテストで確認）、目標 -14 LUFS / -1 dBTP（2026-11-20 決定。Spotify の基準と過去の完成版に合わせる）、MP3 は pedalboard（LAME内蔵、読み書きとも。ffmpeg不要）
  - 文字起こし WhisperX / kotoba-whisper（単語タイムスタンプ）。話者＝トラック、かぶりは音量比較で判定
- 重い処理はサーバー側でトラックごとにキャッシュ、音量・フェード・カット・ダッキングはブラウザでリアルタイム
- 処理エンジンはMCPサーバーとしても公開し、Claude Codeから操作可能に

## 同期（編集点合わせ）
1. 冒頭から拍手候補（鋭い立ち上がり・高域・短い）を検出
2. 全トラックに共通し、ずれが一貫する候補を採用
3. GCC-PHATでサンプル以下の精度で合わせる
4. 冒頭の文字起こし（「せーの」「はい始まりました」等）をClaudeが読み、拍手と本編開始位置を確認
5. 冒頭と終盤のずれを測り、レコーダー間のドリフトを補正

## BGM学習
過去の完成版mp3とBGM原曲を比較して音量カーブを推定 → 完成版の文字起こしと対応付け → Claudeがスタイルプロファイル化 → 新しい回に適用 → UIで修正 → 正解例として蓄積

### 実装状況（2026-11-20）
- `engine/podcast_engine/sync.py` に実装。`python -m podcast_engine sync A.wav B.wav ...` で JSON を出力
- ずれの定義：このトラックでの時刻 = 基準トラックでの時刻 + offset_sec（+ drift_ppm×1e-6×時刻）
- 拍手候補の取り違え対策：候補の組から作った「ずれ」を冒頭全体の相関で検証し、一致する組のうち最も拍手らしいものを採用
- ドリフト：かぶり（相手の声が数ms遅れて入る）で会話の相関が±数msぶれるため、60秒ごとに測り Theil-Sen で直線を当てはめる。測定区間が2分未満なら0
- 実素材での結果
  - 9/25：−2.3967秒（正解＝Resolveでの手作業 −2.3973秒、差0.6ms）。会話全体の相関では −2.39725秒。差は拍手位置から各マイクまでの距離差と考えられる。ドリフト +0.1ppm（13点）
  - 10/02：−2.7965秒（正解データなし）
- 「明瞭さ」（相関ピークと2番目のピークの比）は実素材で1.5前後。部屋の反響で2番目の山が出るため。判定のしきい値に使うには要調整

## プロジェクトファイル（.podproj）と書き出し（2026-11-20 実装）
- `engine/podcast_engine/project.py`（形式）、`render.py`（書き出し）
- 時刻の物差し：カット（edit.segments）は「基準時刻」（同期の基準トラックのファイル内時刻＝文字起こしと同じ）、BGMの位置は「出力時刻」

- 全話者を同じ位置で切る。区間の並べ替えも区間リストの順番で表す
- CLI：`init`（声の素材から作成、同期も測る）／`cut`（基準時刻 or `--output-time`）／`render`（.mp3 / .wav）
- 9/25 を Resolve の値（声の音量、配置、BGM位置・キーフレーム・フェード）で再現して完成版と照合

## ラウドネス調整（2026-11-20 実装）
- 書き出しの最後（マスターのエフェクトの後）に、統合ラウドネスを `output.loudness_lufs` にそろえ、先読みリミッターでトゥルーピークを `output.true_peak_dbtp` 以下にする。リミッターで下がった分は測り直して補う
- リミッターはエフェクト（`{"type": "limiter"}`）としても使える
- 過去の完成版の実測：9/25 は −14.0 LUFS／+4.3 dBTP、10/02 は −14.0 LUFS／+8.8 dBTP → Resolve で −14 LUFS にそろえていて、トゥルーピークは大きく 0 を超えている（機器によっては音割れ）
- 目標は −14 LUFS／−1 dBTP（ユーザー決定）。MP3 は書いた後に読み直して測り、ずれを補正して書き直す
  - MP3化でラウドネスが 0.2〜0.4 LU 下がる → MP3 にする前の目標をその分上げる
  - MP3化でピークが上がることがある → 全体の音量は下げず、リミッターの上限をその分下げる
  - リミッターが強くかかると音量を上げてもラウドネスが上がりにくいので、割線法で合わせる
- 9/25 を再現して MP3 に書き出し：−11.5 → **−14.00 LUFS／−1.23 dBTP**（完成版は −13.99 LUFS／+4.28 dBTP）。128kbps で 20.3MB
- 課題：21分の回の書き出しに約68秒（補正の繰り返しのため。リミッターの計算を速くする余地あり）

## ノイズ除去（2026-11-20 実装）
- 9/25 の 5:00〜5:30 で4通りを聴き比べ、ユーザーが **DeepFilterNet・制限なし（強）** を選択
  - noisereduce はノイズを約20dB減らすが声も5〜8dB削れる。DeepFilterNet は声の大きさをほぼ保つ
- `engine/podcast_engine/denoise.py`。声トラックの `denoise` に書く。素材全体にかけて `.podcache/` に保存し、素材か設定が変わったときだけ作り直す
- 60秒ずつ区切って処理し、1秒重ねてつなぐ（メモリ対策）。PyTorch 2.0.1 に固定（DeepFilterNet が新しい torchaudio と合わない）
- `init` で作るプロジェクトは最初からノイズ除去あり（`--no-denoise` で外せる）
- 9/25 全体：話していない部分 −36.3 → −58.7 dB、話している部分は変わらず。Resolve の完成版は −37.3 dB（Resolve の Noise Reduction はほとんど効いていなかった）→ 過去の回より間がかなり静かになる
- 時間：初回約2分（うちノイズ除去 約1分）、キャッシュがあれば約65秒
- 9/25 全体の書き出し（同期・EQ・フェーダー・Busコンプ・ノイズ除去・BGM・−14 LUFS）をユーザーが試聴して問題なしと確認（2026-11-20）
- キャッシュは FLAC 24bit（可逆圧縮）で保存：9/25 の2トラックで 482MB → 133MB。float で計算し直した値との差は −109dB（24bit の丸め誤差のみ）。0dBFS を超える音があるときだけ 32bit float の WAV
  - 書き出した MP3 同士は −40dB 程度の差が出るが、MP3 の圧縮誤差そのもの（ラウドネス・ピークは小数3桁まで一致）
- テストの注意：DeepFilterNet は本物の声で学習した AI なので、合成の「声」は消してしまう。声が保たれるかは実素材があるときだけテストする

## 文字起こし：実装（2026-11-20）
- `engine/podcast_engine/transcribe.py`、コマンド `transcribe`。出力は `回.transcript.json`（1文字ごとの時刻・フィラーの印、ルビ用）と `回.transcript.txt`（台本：話者・時刻・フィラー抜き。Claude に読ませる形）。時刻は基準時刻
- トラックごとにノイズ除去済みの音を書き起こし、`.podcache/` に保存（2回目以降は約2秒）。9/25（21分×2トラック）で約6分
- 話者の判定：間の詰まった言葉のまとまり（フレーズ）ごとに、各トラックの音量（声の音量調整後）を比べる。他より3dB以上小さいフレーズは相手の声のかぶりとして捨てる。重なりは差の大きい方を優先し、負けた方は重なった言葉だけ捨てる
  - 1文字ずつ比べると「最」「最初の」のように頭の1文字が両方に残った（476発言 → フレーズ単位で 131発言）
  - フレーズを丸ごと捨てると、長いフレーズ（かぶり＋本人の声）で本人の声まで消えた
- 初期プロンプト（言葉のリストを Whisper に見せる）は不採用：プロンプトをそのまま出力したり、「村」を「オムライスラヂオ」に置き換えたりした → 書き起こし後に決めた言い換え（`corrections`）で直す
- 話の終わり：最後の言葉の `end_after_speech_sec`（プリセットで 1.3 秒）後で切る。収録後の雑談（2秒以上の間の後の、確からしさ0.6未満の発言）は除く
  - 9/25：「さよなら」1250.84 秒 → 1252.14 秒で切る（Resolve は 1252.20）。ED の開始 1193.889 秒（Resolve 1193.955）
- BGM の位置は「基準＋相対秒」で持つ（`anchor`: voice_start / voice_end / output_start）。カットや話の終わりの調整に ED がついてくる
- 固有名詞の言い換え（ユーザー確認済み、`presets/okadayama.json` の `corrections`）：内田達郎・内田立郎→内田樹、新平→真兵、施設図書館→私設図書館、ルチャリブロ→ルチャ・リブロ、小辺女学院→神戸女学院、（オ）ムライスラジオ・村井スラジオ→オムライスラヂオ
  - 9/25 で全部直った。冒頭の「内田立郎やってます」は実際は「ルチャ・リブロやってます」の聞き間違いだったので、前後の言葉を含めた長い言い換え（「施設図書館の内田立郎」→「私設図書館ルチャ・リブロ」）を追加。長い言い換えが優先されるので、他の「内田立郎」は「内田樹」のまま
  - 同じ聞き間違いでも直す先が違うときは、前後の言葉を含めた言い換えで分けられる
- 残る課題：同時に話した短い相づちの分け方（「本当／ですね」）、文脈が必要な誤り（言い換えでは直せない。台本の手直しか、フェーズ5で Claude が直す）

## 編集画面：段階1（2026-11-20 実装）
- 画面モック（ユーザー承認済み）：https://claude.ai/artifact/JVSYfdmHii6upsm2dLCD8d（①編集画面 ②BGM ③エフェクト ④EQ・コンプ）。段階1は①の基本
- 構成：`engine/podcast_engine/server.py`（FastAPI。Mac の中だけ 127.0.0.1:8765）＋ `ui/`（React 19・Vite 7・TypeScript 5）。`npm run build` で作った `ui/dist` をサーバーがそのまま配る。開き方：`python -m podcast_engine serve 回.podproj`
- API：GET/PUT /api/project、GET/PUT /api/transcript（文字の修正。.transcript.txt も書き直す。音声は変わらない）、GET /api/peaks/{素材ID}（波形、1秒50点）、GET /api/audio/{素材ID}（試聴用 24kHz・16bit。声はノイズ除去済み）。重い結果は .podcache/ に保存
- 台本：行をクリック→その位置へ移動して文字を直せる（Enter 確定・Esc 取り消し、日本語変換中の Enter では確定しない）。ドラッグ・Shift・⌘クリックで複数選んでカット（Delete キーでも）。続いた行はまとめて1つのカットにする。カット済みの行はクリックで戻す：途中のカットはそのカットを丸ごと、最初より前・最後より後（拍手の前や収録後の雑談）はその行のところまで。⌘Z／⇧⌘Z で元に戻す・やり直し
- 波形：トラックごと、時刻の軸は基準時刻（文字起こしと同じ物差し）。上にルビ（フィラーは灰色、表示幅4分以下のとき）。カット区間は赤。BGM は出力時刻から基準時刻に写して音量カーブを表示（話し始めより前の OP 部分は基準時刻がないので出ない）。全体バーは出力時刻（BGM・カット位置・表示中の範囲）でクリックで移動
- 再生（Web Audio、AudioContext は 24kHz）：同期のずれ・ドリフト、カット（飛ばす。つなぎ目 10ms のクロスフェード）、声の音量・フェーダー（effects の gain）・パン・ミュート、BGM の位置・音量カーブ・フェード、BGM／マスターのフェーダーを反映。EQ・コンプは未反映（次の段階）。代わりに試聴の音量はフェーダーで上げた分を戻して完成版（−14 LUFS）に近づけ、最後に音割れ防止のリミッター

## drpの読み方（判明分）
- 1つのタイムラインに全回が並ぶ。トラック：BGM／青木さん／内田さん／ゲスト（話者＝トラック）
- 時間は「フレーム数|端数(double, little endian 16進)」、24fps、先頭は 1:00:00:00
- クリップは Name／Start（タイムライン位置）／Duration／In（素材内の開始位置）を持つ。BGMの間に1秒のTransition（フェード）
- 音量・エフェクトは `EffectFiltersBA`：先頭9バイトのヘッダー＋zstd圧縮（短いものは非圧縮）。中身はprotobuf
  - filter（field1）が並び、各filterは id（f1）・スロット（f7）・パラメータ（f9: id f1、値 f3 or キーフレーム f10）
  - filter 124＝クリップ音量。param 95＝音量dB（固定値は f3→f1→f2 にdouble）
  - キーフレーム（f10）：4バイトのヘッダーの後に1件72バイト。[フレーム数(クリップ先頭から, 6バイトLE)][0d 02][音量dB(double LE)][0埋め48バイト][カーブ係数(double)]
  - filter 126＝EQバンド（1バンド1filter）。整数値はzigzag符号化（sint：正の値n→2n、負の値n→−2n−1）。Resolve画面と照合済み
    - param 102＝周波数Hz、104＝ゲイン×10 dB、105＝バンド番号（0→B1 … 4→B5）
    - 103＝シェルフ（B2/B5）のみに出る値（1500→750）。画面に表示がなく意味は不明
    - B1（ハイパス）の104（青木さん −31、内田さん −15）も画面に表示がなく不明
    - 初期値の項目は省略される（ベルのQ 1.0、B6 19kHzローパス（オフ）など）。バンドの種類は B1ハイパス／B2ローシェルフ／B3・B4ベル／B5ハイシェルフ／B6ローパスで固定
  - filter 128 は不明（EQ全体のオン/オフ？）
  - Transition の PrettyType は "Cross Fade 0DB"、Duration はフレーム数（24＝1秒）
  - クリップの角をドラッグして付けるフェードアウト：filter 124 の param 98＝長さ（フレーム数、double）、param 100＝カーブの形（16バイト＝ビッグエンディアンのdouble 2つ。例 77/−66、67/−43。形との対応は未解明）
